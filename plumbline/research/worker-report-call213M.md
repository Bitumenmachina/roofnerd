## Answer 2 (F16)
- Why unreadable: a job is saved as a tree; each element's entry lists `children` as a map name -> path (file.rs:47, built from `Job::children()` job.rs:1097). Two children of one parent with one name collide in that map: the second overwrites the first, so one of them (here the material "Plywood", or the item) is listed as nobody's child. `file::load` walks every element up to the job (file.rs:296-312) and refuses with "<path> is not under the job: <path> has no parent". Saving does not check; loading does, so the file is written and can never be read.
- The one-name rule today: `Job::add` refuses a second child of one parent with the same name (exact, job.rs:197-201). Bringing-in (import items, import prices --add, import ifc via keep_name for names, tables) goes through `add` or checks `children()` first.
- Things that can be renamed: (1) an item, `editing::rename_item_inner` (editing.rs:1665): checks only OTHER ITEMS by `same_name`, not materials or any other sibling -> the hole. (2) each thing set down from the item, in the same function: held (`names_in_scope` for the level; a name taken is kept and counted). (3) a thing brought in from a model (ifc `keep_name`, lib.rs:700 and the wall name at lib.rs:1440): held, both check `children()` first. (4) roof planes (solve.rs `rename`, generated "plane N", two-stage so they cannot meet): not an input from a person. The window's Rename item calls (1).

## Answer 5 (point 8): what the figure reader takes for a length
Today (formula.rs `tokens`/`parse`): a number, optionally followed by one unit word (in, ft, mm, cm, m, lf, sf) is a fixed size (`Sized`); names, + - * / ( ) , min( ) max( ); an `x` between two things is times; `'` and `"` and anything else not listed are refused with the character printed through Rust's debug form (`'\''`); two things side by side are refused; `1/2 in` reads as 1 / (2 in) (a plain number over a length: "not a length"). Will take (all of them were refusals before, except the first):
 - `a / b unit` as a fraction of that unit where the first number is not the right-hand side of a `*` or `/` and the unit is not followed by a `*` or `/` (so every formula that read before reads the same; where `*` or `/` stand beside it the old reading is kept);
 - a whole number then a fraction then a unit (`5 1/2 in`): both in that unit;
 - feet then inches (`3 ft 6 in`), and `3'6"`, `3'`, `6"`: `'` after a number is ft and `"` after a number is in; written next to each other they add. A minus is a minus: `3 ft - 6 in` is 3 ft less 6 in and `-1/2 in` is minus a half inch; no `-` is ever read as a joining.
 - the refusal for a mark it cannot hold names it without Rust's quoting and says how to write a length.
The proof (every formula of library/ and of the tests, old reader against new reader, same tree) is a test, `formula_213.rs`, using a copy of the old reader kept as a test fixture; result in the run section below.
